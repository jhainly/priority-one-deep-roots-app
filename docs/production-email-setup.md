# Production Email Setup

The Deep Roots app should send account verification and password reset emails from:

```text
Deep Roots <deeproots-no-reply@priorityone.org>
```

No replies are expected or monitored.

## AWS Setup

Create an Amazon SES identity in the same AWS account and region as the production Cognito user pool:

```text
AWS account: 984454381602
Region: us-east-2
SES identity: priorityone.org
Sender address: deeproots-no-reply@priorityone.org
```

Prefer domain verification for `priorityone.org` instead of verifying only the individual email address. Domain verification lets Cognito send from `deeproots-no-reply@priorityone.org` after Mandi adds the SES DKIM records to DNS.

After SES shows the domain as verified, deploy the Amplify backend so Cognito uses:

```text
FROM name: Deep Roots
FROM email: deeproots-no-reply@priorityone.org
Reply-to: unset
```

The backend sender config is in:

```text
amplify/auth/resource.ts
```

## Needed From Mandi

Ask Mandi to add the DNS records generated by Amazon SES for the `priorityone.org` identity.

SES will normally provide three DKIM CNAME records similar to:

```text
Type: CNAME
Host/Name: [generated-token-1]._domainkey.priorityone.org
Value/Target: [generated-token-1].dkim.amazonses.com

Type: CNAME
Host/Name: [generated-token-2]._domainkey.priorityone.org
Value/Target: [generated-token-2].dkim.amazonses.com

Type: CNAME
Host/Name: [generated-token-3]._domainkey.priorityone.org
Value/Target: [generated-token-3].dkim.amazonses.com
```

Use the exact records shown in the AWS SES console. Leave these records in place permanently.

## Optional MAIL FROM

Custom MAIL FROM can be added later for stronger SPF alignment. A typical value would be:

```text
mail.deeproots.priorityone.org
```

If enabled, SES will provide two additional records:

```text
Type: MX
Host/Name: mail.deeproots.priorityone.org
Value/Target: 10 feedback-smtp.us-east-2.amazonses.com

Type: TXT
Host/Name: mail.deeproots.priorityone.org
Value/Target: v=spf1 include:amazonses.com ~all
```

Only add custom MAIL FROM after confirming the subdomain has no existing email use.

## Current Permission Blocker

The current AWS role cannot manage SES:

```text
arn:aws:sts::984454381602:assumed-role/AWSReservedSSO_amplify-policy_069071964c9d78f5/amplify-admin
```

Minimum additional permissions needed to complete setup:

```text
ses:CreateEmailIdentity
ses:GetEmailIdentity
ses:ListEmailIdentities
ses:PutEmailIdentityMailFromAttributes
ses:DeleteEmailIdentity
```

Delete permission is useful only for correcting setup mistakes and can be omitted if an AWS admin prefers to retain cleanup control.
